# 5ka Moscow Parser

Исследовательский Python-проект для сбора и структурирования публичных данных магазинов сети «Пятёрочка» в Москве: магазины, категории, товары, цены, наличие, промо-механики и расширенные карточки товаров.

Проект построен как возобновляемый ETL-пайплайн: сбор выполняется через реальную браузерную сессию Camoufox, данные сохраняются в SQLite, а результат можно выгружать в CSV и HTML-отчёты.

> Проект не является официальным продуктом X5 Group или «Пятёрочки» и не связан с ними.

## Что реализовано

- поиск магазинов в пределах Москвы через bbox-discovery;
- автоматическое дробление bbox при серверном лимите результатов;
- отделение Москвы от Московской области по данным API;
- сбор дерева категорий и каталога конкретных магазинов;
- обычные и промо-цены, наличие, stock limit, labels и promo-данные;
- обогащение карточек товаров дополнительными атрибутами;
- сбор публичных промо;
- сохранение прогресса в SQLite и продолжение после остановки;
- повторная обработка ошибочных задач;
- экспорт агрегированных данных в CSV;
- генерация HTML-отчёта по отдельному магазину.

## Архитектура

```text
5ka.ru
  │
  ▼
Camoufox browser session
  │
  ├─ cookies / browser state
  └─ dynamic request headers
  │
  ▼
5ka API
  │
  ▼
Parsers
  ├─ stores
  ├─ catalog
  ├─ product details
  └─ promos
  │
  ▼
SQLite
  ├─ resumable task state
  ├─ retry/error state
  └─ collected data
  │
  ├──────────────► CSV export
  └──────────────► HTML store report
```

## Почему используется браузерная сессия

Часть запросов использует служебные заголовки, которые формируются во время реальной сессии сайта. Поэтому проект запускает Camoufox, получает необходимые заголовки из сетевых запросов страницы и выполняет API-запросы в контексте этой сессии.

Сессионное состояние сохраняется локально в `5ka_storage_state.json`. Этот файл намеренно исключён из Git.

## Полнота каталога

Catalog endpoint ограничивает размер одной выдачи. Сборщик использует лимит 499 и при достижении лимита пытается рекурсивно разделить задачу по диапазону цен.

Если диапазон больше нельзя корректно разделить, задача получает статус `saturated`, а каталог магазина не помечается как полностью собранный. Это позволяет не выдавать потенциально усечённый результат за полный.

## Установка

Требуется Python 3.13.

```bash
python -m venv .venv
source .venv/bin/activate

python -m pip install --upgrade pip
pip install -r requirements.txt
python -m camoufox fetch
```

На Windows активация окружения будет отличаться:

```powershell
.venv\Scripts\activate
```

## Использование

Сначала рекомендуется выполнить небольшой пилот, а не запускать полный сбор.

### Получить магазины Москвы

```bash
python main.py stores
```

### Проверить каталог на одном магазине

```bash
python main.py catalog --limit-stores 1
```

### Обогатить ограниченное количество товаров

```bash
python main.py details --limit-products 20
```

### Собрать публичные промо

```bash
python main.py promos
```

### Экспортировать CSV

```bash
python main.py export
```

### Посмотреть состояние локальной базы

```bash
python main.py status
```

### Повторить задачи со статусом error

```bash
python main.py retry-errors
```

### Безопасный pilot-run

```bash
python main.py pilot --stores 1 --details 20
```

### HTML-отчёт по магазину

После того как магазин и его каталог уже находятся в локальной SQLite:

```bash
python -m reporting.client_report --sap 300R
```

Отчёт и CSV-файлы создаются локально в `exports/` и не коммитятся в репозиторий.

## Локальные данные

Репозиторий намеренно не содержит:

- browser storage state и cookies;
- локальную SQLite-базу;
- CSV/HTML-выгрузки;
- `.env` и другие локальные секреты;
- IDE/virtualenv-файлы.

Это позволяет публиковать код без публикации пользовательской сессии и собранных runtime-данных.

## CAPTCHA и антибот-защита

Проект **не обходит CAPTCHA автоматически**.

Если сайт показывает проверку, Camoufox остаётся открытым для ручного прохождения. После этого процесс можно продолжить.

На длительных массовых прогонах антибот-защита остаётся главным практическим ограничением проекта. Поэтому текущая версия лучше подходит для контролируемых выборок и исследования данных, чем для полностью автономного непрерывного сбора всей сети.

## Статус проекта

Проект завершён как рабочий исследовательский прототип для Москвы. Основные технические задачи — discovery магазинов, возобновляемый сбор каталога, дедупликация, контроль полноты, хранение состояния и отчётность — реализованы.

Дальнейшее масштабирование на большой непрерывный сбор ограничено антибот-защитой целевого сайта и не является целью текущей версии.
