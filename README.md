# 5ka Moscow Parser v0.4

Пилот проекта только для Москвы.

## Что делает

1. Собирает магазины из актуального bbox API 5ka.
2. Автоматически дробит bbox, если сервер возвращает лимит 500.
3. Отделяет Москву от Московской области по `region_id=14`.
4. Для московских магазинов собирает:
   - дерево категорий;
   - товары;
   - обычную цену;
   - скидочную цену;
   - наличие/stock limit;
   - labels / promo;
   - изображения и базовые свойства.
5. Опционально обогащает уникальные товары полной карточкой:
   описание, бренд, страна, состав, атрибуты, нутриенты.
6. Сохраняет публичные промо 5ka.
7. Экспортирует CSV.

Все этапы сохраняют прогресс в SQLite и рассчитаны на продолжение после остановки.

## Почему Москва определяется не только bbox

Расширенный bbox покрывает всю Москву, включая Новую Москву, и неизбежно
захватывает Московскую область. В живых ответах 5ka:

- `region_id=14` — Москва;
- `region_id=18` — Московская область.

Поэтому bbox используется только для discovery, а итоговая выборка — по данным
самой 5ka.

## Команды

Собрать магазины:

```bash
python main.py stores
```

Контрольный каталог одного магазина:

```bash
python main.py catalog --limit-stores 1
```

Обогатить первые 20 уникальных товаров:

```bash
python main.py details --limit-products 20
```

Публичные промо:

```bash
python main.py promos
```

Экспорт:

```bash
python main.py export
```

Статус:

```bash
python main.py status
```

Полный безопасный smoke/pilot:

```bash
python main.py pilot --stores 1 --details 20
```

После успешного пилота полного московского каталога:

```bash
python main.py catalog
python main.py details
python main.py promos
python main.py export
```

## Выходные файлы

SQLite:

```text
data/5ka_moscow.sqlite
```

CSV:

```text
exports/stores_moscow.csv
exports/products.csv
exports/store_products.csv
exports/offers_moscow.csv
exports/public_promos.csv
```

`store_products.csv` может стать очень большим. SQLite является основным
полным хранилищем; CSV — экспортным представлением.

## Полнота каталога

Текущий catalog endpoint поддерживает `limit < 500`. Сборщик использует 499.
Если листовая категория возвращает ровно 499 товаров, задача автоматически
делится по диапазону цены. Результаты дедуплицируются по `(SAP, PLU)`.

Если диапазон невозможно разделить, task получает `saturated`, а магазин
не помечается `complete`. Таким образом код не выдаёт усечённый каталог за полный.
